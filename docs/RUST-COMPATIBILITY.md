# Rust Compatibility Inventory

Historical T01 inventory; current runtime behavior is in
[RUST-RUNTIME.md](RUST-RUNTIME.md) and [QUALIFICATION.md](QUALIFICATION.md).
In particular, Rust correctly byte-swaps the raw SHA nonce word for Stratum
submission; the C submission formatting below is a reference behavior, not the
Rust wire contract.

Generated for task T01 from the `igpu-vulkan` branch baseline. This is a recon
and compatibility inventory only; it is not a claim that the Rust/Vulkan rewrite
is implemented.

## 2. Core semantic types (Part 9)

These are specified in `docs/rust-vulkan-planning/09-contracts.md` and must be
defined in Rust before GPU/runtime workers start. C equivalents are shown for
mapping only.

## 3. Byte order and target mapping

Proof references: `gbtc_target_to_raw_hash` in `src/stratum_protocol.c:110`,
`gbtc_raw_hash_meets_target` in `src/stratum_protocol.c:122`,
`gbtc_work_hash` in `src/bench.c:95`, `build_header_midstate` in
`src/main.c:516`, and `tests/test_stratum_protocol.c`.

| Field | Wire hex meaning | Serialized header bytes | CPU `u32` meaning | GPU `u32` meaning | Submit hex meaning |
| --- | --- | --- | --- | --- | --- |
| version | 8 hex chars, big-endian (`version_be`, parsed with `read_be32`) | bytes 0-3, little-endian (`hdr[0..3]`) | `s->version_be` numeric big-endian value | not in `WorkBatch` | not submitted; job context only |
| prevhash | 64 hex chars, internal byte order (`prevhash[0..31]`) | bytes 4-35, each 4-byte word reversed | byte array, no single u32 | not in `WorkBatch` | not submitted |
| merkle root | 32 bytes from `sha256d` (big-endian SHA output) | bytes 36-67, copied as-is | byte array `mr` | `tail3[0]` = bytes 64-67 interpreted big-endian (last merkle word) | not submitted |
| ntime | 8 hex chars, big-endian (`ntime_be`) | bytes 68-71, little-endian | `s->ntime_be` numeric big-endian value | `tail3[1]` = byte-swap of `ntime_be` so GPU block bytes are little-endian | `stratum_submit` formats `ntime_be` as `%08x` (big-endian hex) |
| nbits | 8 hex chars, big-endian (`nbits_be`) | bytes 72-75, little-endian | `s->nbits_be` numeric big-endian value | `tail3[2]` = byte-swap of `nbits_be` | not submitted |
| nonce | candidate value generated by GPU/CPU | placeholder bytes 76-79 are zero in midstate; GPU places nonce as big-endian word in second SHA block | `result.nonces[i]` | `nonce_base + invocation index`, treated as big-endian SHA word | `stratum_submit` formats candidate as `%08x` (same numeric value) |
| midstate | derived from first 64 header bytes | SHA-256 compression of bytes 0-63 | `midstate[0..7]` SHA state words | `I.midstate[0..7]` / `I[0..7]` | not submitted |
| target limbs | `target[0..7]`, where `target[0]` is most-significant comparison limb | not serialized in header | `work.target[0..7]` | only `target[0]` used as prefilter threshold | not submitted; full hash must satisfy `gbtc_raw_hash_meets_target` |

Additional target rules:

- Difficulty conversion: `gbtc_target_from_difficulty` in `src/stratum_protocol.c:70`.
- Target-to-hash proof: `gbtc_target_to_raw_hash` in `src/stratum_protocol.c:110`.
- Full comparison: `gbtc_raw_hash_meets_target` in `src/stratum_protocol.c:122`.
- GPU one-word prefilter: `BSWAP32(final SHA-256 output word 7) <= target[0]`
  in `src/gles_tuning.c:309` and `src/opencl.c:464`, `515`, `567`.
- Full candidate verification before submission: `gbtc_work_hash` plus
  `gbtc_raw_hash_meets_target` in `src/main.c:1794-1800`.
- A one-word GPU prefilter is necessary but not sufficient.

## 4. Backend selection and migration

- Backend names accepted by `gbtc_parse_backend_kind`: `gles`, `vulkan`, `opencl`
  (`src/backend.c:21-33`).
- `auto` is defined by `gbtc_backend_is_auto` as NULL, empty string, or `"auto"`
  (`src/backend.c:16-19`).
- Runtime auto priority is `gles`, then `opencl`, then `vulkan`
  (`src/main.c:1378-1382`, `1428-1437`). This differs from README wording.
- Explicit `GBTC_BACKEND` values are parsed and the selected backend is probed;
  failure is fatal (`src/main.c:1403-1411`).
- Probe-only mode prints `gles`, `opencl`, `vulkan` in that order
  (`src/main.c:1423-1440`).
- The C Vulkan backend is an unavailable placeholder
  (`src/backend.c:54-71`).
- OpenCL platform selection prefers a vendor platform over Mesa Rusticl/Clover
  unless `GBTC_OPENCL_PLATFORM` is set (`src/opencl.c:690-720`).
- OpenCL does not read `GBTC_DEVICE`; it selects by OpenCL platform/device and
  reports environment/default device path separately (`src/opencl.c` has no
  `GBTC_DEVICE` access; `src/main.c:1362` sets status path).

- `history` presence follows initial/incremental rules: `/status.json` always
  requests history; SSE initial requests history; SSE updates do not

- JSON escaping is used for all synthetic/status strings
  (`gbtc_json_escape` in `src/stratum_protocol.c:434`).

## 8. GLES retirement migration

Old configuration:

```sh
GBTC_BACKEND=gles
GBTC_GLES_KERNEL=altbool
GBTC_GLES_LOCAL_SIZE=16
GBTC_GLES_AUTOTUNE=0
```

New configuration example:

```sh
GBTC_BACKEND=vulkan
GBTC_VULKAN_LOCAL_SIZE=64
GBTC_VULKAN_POLL_US=1000
GBTC_VULKAN_VALIDATION=0
```

or, while retaining the existing fast path:

```sh
GBTC_BACKEND=opencl
GBTC_OPENCL_KERNEL=unrolled
GBTC_OPENCL_LOCAL_SIZE=64
GBTC_OPENCL_SIMD=auto
GBTC_OPENCL_POLL_US=1000
```

Required behavior:

- If any `GBTC_GLES_*` setting is active while GLES is retired, the Rust
  runtime must return an explicit error with migration instructions. It must not
  silently substitute Vulkan or OpenCL.
- Remove injected GLES defaults from candidate Compose and launcher configuration
  before running the Rust binary (`GBTC_GLES_KERNEL`, `GBTC_GLES_LOCAL_SIZE`,
  `GBTC_GLES_AUTOTUNE`).
- OpenCL controls may remain configured while Vulkan is selected; validate their
  values only when the OpenCL backend is actually selected.
- `GBTC_ALLOW_BATTERY`, `GBTC_SHADER_CACHE`, and `GBTC_IGC_FORCE_SIMD` behavior
  must be preserved by the launcher/driver mapping.
